#### Findings

**Finding 1 — MEDIUM. Tier attribution is silently inert for any acceptance
tier not under a `tests/acceptance` package path, and says nothing when it
attributes nothing.**

`internal/acceptance/scope.go:8` fixes `AcceptancePath = "tests/acceptance"` as
a compile-time constant; there is no config key for it (a grep over
`internal/config` finds no `acceptance_path` / `AcceptanceDir` of any kind).
`Scope.counts` therefore discards every Go result and every Gherkin summary
whose package block does not match that literal, case-sensitively.

Under a whole-repo `ScopeMixed` command — the classification for the single most
common configuration, `go test ./...`, and the one this repo itself ships —
that turns skip detection into a silent no-op for any project whose acceptance
tier lives elsewhere. Reproduced against the branch binary, each in its own
throwaway repo, all with `acceptance_skip_policy` at its default:

| Report (command: `sh ./run.sh # go test -v ./...`) | Result |
|---|---|
| `--- SKIP: TestA` + `ok gv/tests/acceptance` (control) | **exit 1** — correctly fails |
| `--- SKIP: TestA` + `ok gv/Tests/Acceptance` | exit 0, bare `✓` |
| `--- SKIP: TestA` + `ok gv/features` | exit 0, bare `✓` |
| `--- SKIP: TestA` + `ok gv/test/acceptance` | exit 0, bare `✓` |
| `0 scenarios` + `ok gv/features` | exit 0, bare `✓` |

`gv/features` is the conventional godog/cucumber layout, and godog is one of the
three runners the classifier explicitly names.

Two things make this a truthfulness problem rather than a scoping choice:

- **It is silent.** The output is a bare green `✓` with no detail — no note, no
  `⚠`. That contradicts the design principle this very feature establishes and
  applies everywhere else: `parseGoNonVerbose` returns a recognised shape with
  `SkipData:false` precisely so the operator is *told* the report cannot carry
  skips (`go test (non-verbose) carries no skip data — add -json or -v …`), and
  `UnparseableDetail` exists so an unrecognised shape is *told* too. The
  zero-attribution case is the third member of that family and is the only one
  that says nothing.
- **The feature brief does not carve it out.**
  `docs/features/truthful-validators.md:90` (AC2) states without qualification
  that for *each* acceptance-classified command "a detected skipped / pending /
  undefined scenario (or a `0 scenarios` run) makes the command **fail** by
  default". AC5 (`:107`) describes the guard as "classification gates the parse,
  and the parse gates the verdict" — the tier-attribution layer rounds 1–2 added
  is not described in the brief at all, and the brief's edge-case list
  anticipates only the over-block direction ("a Go run where a *non*-acceptance
  package skips and an acceptance package does not"), never this under-block
  direction.

Mitigations that keep this out of CRITICAL: the limitation *is* stated in the
`[validate]` comment block of both `centinela.toml` and the scaffold asset
("within a combined whole-repo command … only results attributable to
`tests/acceptance` are counted"); Centinela's own workflow gate mandates
`tests/acceptance/` as the acceptance tier, so governed projects match by
construction; and a project that runs its acceptance tier through a path-scoped
or named runner command gets full, unfiltered detection — I verified that an
`acceptance test`-scoped command does fail on a `gv/features` skip.

**Affected spec:** AC2 (`docs/features/truthful-validators.md:90-96`), AC5
(`:107-110`).
